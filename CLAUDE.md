# Hachures

## Project overview

- Rust 2024 workspace with one member: `game/`.
- Game engine: Bevy 0.20.
- Browser target: `wasm32-unknown-unknown`.
- Runtime assets live under `game/assets/`.
- Generated browser output is written to `website/play/`.

## Design source of truth

- `docs/bible.md` (French) is the game design: story, worlds, rules, bestiary, numbers. **When the code and the bible disagree, the bible wins**: the code has a bug. A rule changes in the bible first, and only with the owner's say. Code comments cite it as "docs, section N".
- `docs/direction-artistique.md`: the art direction (a relief model filmed like a miniature). `docs/3d-assets.md`: when a board object is built in code and when it is an asset. `docs/art-prompts.md`: the prompts for every image in `game/assets/ui/`; until a file exists the game draws a plain fallback.

## Game data

- **Level** (`data/levels/<world>-<n>.ron`, read as `LevelData` in `level/data.rs`): `name` (an i18n key), `at` (where the sheet lies on the Marches), `world`, `sepia`, `tools`, `grants` (tools winning it earns for good), `events` (waves the world event starts at), `map` (rows of characters), `waves` (per wave, `(species, count)`), and optional `notes`, `challenge`, `choice`, `alt_refuge`, `shorter`, `changes` (scripted map changes: `(wave, at, becomes)`), `places` (named places).
- **Map characters** (`Grid::parse`): `.` Sol, `,` Sol bas, `b` Boue, `r` Ronces, `~` Eau, `g` Gué, `#` Barricade, `^` Roc, `e` Éboulis, `p` Palissade. Markers stand on Sol: `S` spawn, `F` allies' start, `M` Cible, `B` Borne-Mère, `R` Refuge, `X` Sortie, `W` where the Refuge moves if `alt_refuge`'s choice went that way.
- **World** (`data/worlds/<n>.ron`): its event (`cells` it hits, what they `becomes`, the tiles it `spares`, how many waves it `lasts`, the `announce`/`during`/`refuse_next`/`refuse_after` keys) and its boss (phases, each with its species and `until` HP fraction).
- **Species** (`data/species.ron`): `goal`, `hostile`, `hp` (relative to the Chaîneur's 100), `speed`, `loot`, `weak_to`, `reading` (Pente prices tiles by `costs`; Ombre prices cells by the towers covering them) and `costs`: **a tile left out of `costs` is impassable** for that species.
- **Towers** (`data/towers.ron`): damage, range and splash in tiles, cooldown, pin and slow in seconds.
- **Adding a level**: write the file, add it to `LEVELS` in `level/data.rs` (the campaign order), give it an `at`, add its keys (`level.<id>.name`, its notes and places) to every i18n file, then run `cargo test -p game levels` (every level loads, and every species reaches its goal with and without the event) and the balance bot.

## Assets

- `game/assets/` keeps only what the game loads; the rest of each pack stays in `../Hachures-asset-library/`.
- Every asset has a row in `game/assets/CREDITS.md` (author, licence, source); AI-generated art says so.
- `build-web.sh` copies the runtime folders whole: a new runtime folder must be added to its `cp` line.
- Our own files are kebab-case; third-party files keep their pack's names. Sounds are grouped by kind (`sfx/impact/`, `sfx/foley/`).

## Dev tools

- **Screenshot harness** (`shot/`): F12 saves to `screenshots/`. `HACHURES_SHOT=out.png` jumps into play, saves a shot after `HACHURES_AT` seconds (a comma list takes several) and quits. Also: `HACHURES_SCREEN=title|plan|paused|settings|lexique|controls|credits`, `HACHURES_LANG=en`, `HACHURES_LEVEL=n` (index in `LEVELS`), `HACHURES_DEMO=1` (one tower of each kind and a few barricades), `HACHURES_PARADE=1` (one still figure of each species in a row), `HACHURES_FASCINES=1`, `HACHURES_WAVE=1` (`n` sends wave n at once), `HACHURES_CALQUE=1` (le Calque on), `HACHURES_CAM=x,y,z,tx,ty,tz`, `HACHURES_WALK=n@t`, `HACHURES_TRAVEL=n@t`, `HACHURES_INK=t`, `HACHURES_HOVER=tower|enemy|<cell>` and `HACHURES_TOOL=n` (point without a mouse: range circle, enemy card), `HACHURES_CARD=n` (hover tool card `n`: its tooltip), and `HACHURES_FPS=1` (frame and per-pass GPU times). The harness changes settings in memory only; point `XDG_DATA_HOME` at a scratch folder to keep the real save untouched. Running the binary directly needs `BEVY_ASSET_ROOT=game`.
- **Balance bot**: `cargo test -p game balance -- --ignored --nocapture` plays every level with a simple tower strategy and prints a table (won, Rôle, Names, towers, sépia, losses per wave). It is deterministic and checks the table against `game/tests/balance.txt` (CI runs it too): a rule or data change that moves it fails. Read the diff, then rerun with `HACHURES_BLESS=1` to keep the new table.

The game's world keeps its French names in code, data and files (they are names in the fiction); engineering words are English.

| Term | Meaning | In code |
|---|---|---|
| Nève | the cartographer the player plays | |
| les Marches | the land of the campaign | `overworld` |
| le Grand Plan | the Marches seen from above, Nève walking from sheet to sheet | `Screen::Plan` |
| a sheet (*feuille*) | one level's board | `Level`, `overworld::Sheet` |
| sépia | the ink every tool costs; enemies shot down pay it | `Level.sepia` |
| the Cible | the place a level defends (the Moulin…); the HUD shows what it still holds | `Goal::Cible`, `Level.lives` |
| le Rôle des Noms | the roll of names engraved at the Moulin; losing all `lives` loses the Rôle | `Level.names`, `Save::names` |

| les sceaux | seals won per level (victory, challenge), spent in l'arbre des sceaux | `Save::sceaux`, `menu/sceaux.rs`, `campaign/skills.rs` |
| le carnet | Nève's notebook: the margin notes in play, the campaign read back at the end | `ui` margin, `menu/carnet.rs` |
| le Lexique | L: every tool and species met, with its real numbers; an entry unlocks the first time it shows on the sheet (`???` before). The tool tooltip and the enemy card show the same lines | `Save.seen`, `campaign/lexique.rs`, `menu/lexique/` |
| le Calque | F1: the overlay of every species' route | `Selection.calque` |
| le Droit de Passage | nothing may be inked that leaves a land species without a path, now or on a map to come | `ink/passage.rs` |
| la Crue, le Gel | world 1 and 2 events, announced a wave ahead | `World.event`, `Level.event_on/next` |
| la Tension de la feuille | hidden difficulty gauge, −2 to 2 | `Level.tension` |
| Fuyards | non-hostile walkers heading for the Refuge; they bring Names | `Species.hostile == false` |
| Chaîneur, Échassier, Jalonneur, Gens du Col… | the imperial species | `data/species.ron` |
| la Grande Chaîne | world 1's boss, in phases | `combat/boss.rs`, `World.boss` |
| bornes, Borne-Mère | imperial markers the boss plants; the Jalonneurs' goal | `Grid.bornes`, `Goal::BorneMere` |
| Gratter | a power: scrapes a borne off a cell (the ground under it stays), or returns an Éboulis or a Palissade to plain Sol, and nothing else (never Nève's own ink). Never costs a Name and is never needed to win a level; a scrape is final for Nève. Earned by beating world 1's boss | `TOOLS` "gratter", `Act::Scrape`, `LevelData.grants` |
| Éboulis | fallen stone on a cell, slow to walk; Gratter scrapes it | `Tile::Eboulis`, map char `e` |

| Pente, Ombre | how a species reads the land: by tile costs, or by the towers' shadow | `Species.reading` |

## Common commands

Run from the repository root:

```sh
# Format
cargo fmt
cargo fmt --check

# Check and test
cargo check
cargo test -p game

# Run the desktop game with faster development iteration
cargo run -p game --features dev

# Build a release binary
cargo build --release -p game

# Build the browser version
./scripts/build-web.sh
```

The web build requires the target and matching wasm-bindgen CLI:

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version <version from Cargo.lock>
```

Serve the generated site over HTTP, for example:

```sh
python3 -m http.server -d website
```

Then open `/play/`.

## Development conventions

- Keep application code in `game/src/`; keep game data and assets in `game/assets/`.
- Use `cargo fmt` and preserve the repository's `rustfmt.toml` settings.
- Prefer targeted validation (`cargo check`, `cargo test -p game`) for code changes.
- Do not edit generated files under `target/` or `website/play/`; regenerate them with the documented commands.
- The workspace uses release profile optimizations and a custom `wasm-release` profile; avoid changing profiles unless the build requirements change.

## Code structure

Checked by the build: break a rule and CI fails. Don't work around a check; change the code.

- **One file, one job.** The file's `//!` line names its job in one sentence. If the sentence needs an "and" between unrelated things, split the file. Related files share a folder with a `mod.rs`.
- **A file has at most 200 lines of code.** Blank lines, comments and the `#[cfg(test)]` module don't count. `game/tests/structure.rs` lists the files over the limit.
- **A function does one thing, in at most 70 lines.** `clippy::too_many_lines` enforces this; the threshold is in `clippy.toml`. A system reads, decides, and hands off to named helpers. A UI tree is built one section at a time (`spawn_header`, `spawn_row`, …).
- **Don't silence structure lints** (`too_many_lines`, `too_many_arguments`, `type_complexity`). Group `Local`s in a struct (`map::cells::Drawn`), group queries and resources in a `#[derive(SystemParam)]` (`settings::apply::Due`, `map::land::Landing`), or split the system.
- **Data may be imported from anywhere; behaviour follows the layers.**
  - Data means plain types, tables and pure functions, with no systems and no ECS access (`flow::fields`, `tool_index`): `Tile`, `Grid`, `Species`, `Weapon`, `TowerStats`, `Skill`, `TOOLS`, `Trigger`, `Save`, `BossFile`. The toolkit counts as data too: `theme`, `look`, `storage`, `i18n`, `ui::widgets`.
  - Systems, spawn functions and plugins are layered, from low to high: `schedule` → `settings` → `level` → `campaign` → `map` → `ink` → `combat` → `overworld` → `ui` and `menu` (peers: their buttons open each other's pages), with `shot` (the dev tool) on top. A module may use the behaviour of the layers below it, never above.
  - App-wide state (`Step`, `Screen`, `over_world`) lives in `schedule.rs`.
- **A feature never calls another feature's systems or spawn functions.** It sends a message instead: `LoadLevel`, `Travel`, `WalkTo`, `TowerInked`. Every level, a replay included, starts through `LoadLevel`.
- **Ordering against another feature's system is declared by the higher module.** `combat` orders itself `.before(level::finish_level)`; `level` doesn't name combat's systems. A run condition belongs to the module whose state it reads: `level` adds `Step::Simulate.run_if(alive)`.
- **What the player points at and has picked is not level state.** The tool, the route shown, le Calque and the hovered cell live in `ink::Selection`; `Level` holds the level and the run.
- **Shared values have one home.** Colours, fonts and the type scale live in `theme.rs`: text is `TITLE_SIZE` 56, `HEADING_SIZE` 30, `SUBTITLE_SIZE` 26, `BODY_SIZE` 22 or `SMALL_SIZE` 18; only display type (the game's name, the wave stamp) has its own size. A literal used in two places (a number, an asset path) becomes a named const next to its owner.
- **Persisted data goes through `storage`.** `Save` (campaign progress) and `Settings` (player preferences) are separate resources and separate files. Change a field's meaning and you must migrate the files saved before.
- **Tests** go at the end of the file in `#[cfg(test)] mod tests`, or in a sibling `tests.rs` when large. Neither counts toward the limits.

## Languages

- One resource file per language: `game/assets/data/i18n/<code>.ron`, key → text. `fr.ron` is the reference; every language has exactly its keys. No player-visible text is written in the code or in the level, world and species files: they hold keys.
- Keys are `area.thing`, lowercase with dots: `menu.settings`, `hud.wave`, `tool.barricade`, `level.1-1.name`, `note.1-1.<slug>`, `place.<slug>`, `choice.<id>.<option>`, `world.1.during`, `boss.<boss>.<phase>`.
- In code: `t("key")` for a line, `tf("key", &[&n])` for a line with values (`{}` in order, `{1}` by position so a translation can reorder), `tp("key", n, &[..])` for counts (`key.one` / `key.other`, plus `.few`/`.many` where a language needs them), `n_("key")` for a key kept in a table and shown later with `t`.
- Adding a line: put the key in `fr.ron` and in every other language file, use it, then run `cargo test -p game i18n`: it lists the keys `fr.ron` lacks or no longer needs, and what each other file misses against `fr.ron`. Dev builds also log any key shown without its line.
- Adding a language: copy `fr.ron` to `<code>.ron`, translate it (keep `language.name` as the language names itself), and add one entry to `LANGUAGES` in `game/src/i18n.rs` with its plural rule; the settings offer it at once. IM Fell and Atkinson Hyperlegible cover Western European Latin only.
- Saves keep scratched-out places by key (save version 2); older saves with French names are converted on load. Version 3 adds `seen` (the Lexique), backfilled from the levels already won.

## Test and build output

- Run the smallest relevant test target or filter first, rather than the full suite.
- Keep command output bounded; use `--quiet` where supported and show only the last useful lines for noisy builds.
- Preserve command failures when truncating output:

```sh
set -o pipefail
cargo test -p game --quiet 2>&1 | tail -n 40
```

- Do not paste large generated logs or build artifacts into the working context; inspect focused errors and rerun narrowly when needed.

## Delegation

The main session runs on Opus. Work goes to the cheapest model that can do it, using the agents in `.claude/agents/`. Use them without being asked:

- **Haiku**: the answer or edit is fully specified, no judgment.
- **Sonnet**: Opus has decided *what*; the agent decides *how* inside one clear scope.
- **Opus**: design, root-cause debugging, cross-cutting decisions, reviewing what the helpers return.

| Task | Agent | Model |
|---|---|---|
| Find files, symbols, call sites, i18n keys, assets (more than one search) | `finder` | Haiku |
| Run cargo check/test/fmt/clippy, the web build, git status/log/diff | `runner` | Haiku |
| Read a long file, log or doc to answer one question | `summarizer` | Haiku |
| A fully specified edit: rename, given i18n text in every language, RON value changes | `mechanic` | Haiku |
| Crate docs, changelogs, versions, summarizing a URL | `web-lookup` | Haiku |
| Write code from a spec Opus decided: a system, a feature in one or two modules | `implementer` | Sonnet |
| Compiler errors, clippy warnings, tests broken by an intended change | `fixer` | Sonnet |
| Unit tests for given functions or behaviour | `test-writer` | Sonnet |
| Translate i18n text: new keys, a new language, plural forms | `translator` | Sonnet |
| First-pass review of the diff or given files | `reviewer` | Sonnet |
| How something works end to end across several files | `tracer` | Sonnet |

- Do it inline instead when it is one Read of a known path, one Grep, or an edit of a few lines. Starting an agent costs more than that.
- Give each agent a self-contained prompt with exact paths, keys, values and, for Sonnet agents, the spec and the acceptance check. They start with none of the conversation's context.
- Opus reviews what comes back: after `mechanic`, `implementer`, `fixer`, `test-writer` or `translator`, check `git diff --stat` and read the diff when the change is not trivial; verify `reviewer` findings before acting on them.
- Start independent helpers in parallel, in one message.
