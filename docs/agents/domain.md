# Domain docs

How to use this repo's domain documentation when exploring the code.

## Before exploring, read these

- **`docs/agents/glossary.md`**: the game's terms, and where each lives in code.
- **`docs/bible.md`** (French): the game design, its rules and numbers. AGENTS.md says how it wins over
  the code.

## Use the glossary's vocabulary

When your output names a domain concept (in an issue title, a refactor proposal, a hypothesis, a test
name), use the term as defined in the glossary. Don't drift to synonyms (a *sheet* is a level's board,
*sépia* is the ink, *the Cible* is what a level defends).

If the concept you need isn't in the glossary yet, either you're inventing language the project doesn't
use (reconsider) or there's a real gap: add the term to the glossary.

## Flag bible conflicts

If your output contradicts the bible, say so explicitly rather than silently overriding it. A game rule
changes in the bible first, and only with the owner's say.
